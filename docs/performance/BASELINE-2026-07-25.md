# Performance baseline — 2026-07-25

This is the PERF-002 “before optimization” baseline. It was captured from the normal Release application using the deterministic PERF-001 fixtures.

## Test system

- OS: Windows 10.0.26200
- Runtime: .NET 10.0.5, x64
- CPU: AMD64 Family 25 Model 116, 16 logical processors
- Available memory reported to .NET: 16.3 GB
- Git revision: `16ea282` plus the uncommitted PERF-001/PERF-002 working tree
- Fixture seed: `20260725`

The app window remained visible during every run. “Cold” means the first fresh process in the sequence; the Windows standby list was not forcibly purged. Warm figures are medians of fresh subsequent processes. Each process switched through all six library tabs twice and drove 180 rendered frames through the real album gallery. The cold process also scanned 1,000 generated 44.1 kHz WAV files and measured three seconds of shared-WASAPI playback using generated silence.

## Findings

1. **Folders is the dominant navigation stall.** Its sidebar is an `ItemsControl` inside a `ScrollViewer`, so every folder card is created rather than virtualized. The 50k fixture contains 2,500 folder groups.
2. **Artwork scrolling is dominated by main-thread work.** The gallery uses a non-virtualizing `WrapPanel`; adding another page replaces the entire `GalleryGroups` array, recreating bindings and synchronously decoding images through `ArtworkThumbnailConverter`.
3. **Memory is already over the 300 MB target.** Group cards retain full track arrays for albums, artists, genres, and folders, while rendered image objects add further pressure.
4. **Songs and Playlists scale with collection size.** Songs applies a 50k-item collection, while playlist construction currently loads each playlist’s tracks with separate queries.
5. **The storage/audio path is not the visible bottleneck.** Scan throughput exceeded the 1,000 files/s target with no failures, and normalized idle/playback CPU remained below 2%.

These findings determine the next optimization work: virtualized panels and incremental collections first, followed by asynchronous artwork decode/cache work and query/group instrumentation.
