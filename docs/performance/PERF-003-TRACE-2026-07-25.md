## Conclusions

1. The view-model navigation command itself is not responsible for the multi-second visible pause. Command-to-first-render is roughly nineteen times the maximum command-application time.
2. The 500-cover fixture caused 3,772 file checks and 1,425 bitmap decodes in one navigation/scroll sequence. The application is repeatedly realizing views and decoding the same cover sizes after weak cache entries are reclaimed.
3. Gallery page changes replace the current array twelve times, causing prior items to be rebound and re-realized.
4. Library retrieval and group construction contribute about 204 ms of warm startup, but they do not explain the much larger render stalls.
5. Twenty playlists produced twenty separate track queries, confirming the playlist N+1 pattern.

The trace supports fixing `VIEW-001`, `VIEW-003`, `ART-001`, `ART-003`, and `ART-004` before tuning SQLite.
